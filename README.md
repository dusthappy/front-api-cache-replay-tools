# API Cache Replay

**接口缓存与回放**。按页面管理接口，自动缓存真实响应，一键回放与刷新，加速本地前端调试。

这是仅面向 Chrome 桌面的 Manifest V3 本地扩展，当前版本 **0.7.5**。原始需求与 20 组验收场景保存在 [docs/brief](docs/brief/)。0.2.0 起按用户要求默认开启缓存，0.3.0 增加实际 API 范围自动识别与展示，0.4.0 修复自动模式跨页面刷新复用和 userInfo 路径误判，0.5.0 增加逐接口强制缓存，0.6.0 显示真实请求原因；原交接文档中的“默认关闭、手动配置范围与身份、POST 逐个确认”由当前行为取代。

## 安装与首次使用

1. 使用 Node.js 22.12+（本次开发环境为 Node.js 24.20.0），运行 `npm ci`，再运行 `npm run build`。
2. 把 **dist 中的全部文件**复制到 **releases 下新建的 api-cache-replay-0.*.* 文件夹**，确保第一层包含 manifest.json。构建不会自动更新 releases。打开 `chrome://extensions`，更新时先移除旧扩展，再开启“开发者模式”、点击“加载已解压的扩展程序”，选择刚准备好的新文件夹。
3. 在当前网站点击 Chrome 右上角拼图形状的“扩展程序”按钮，选择 API Cache Replay，或点击已固定的插件图标，打开网站设置；前端网站地址默认填入 **`http://localhost:3000/`**（可修改），保存并授予该主机权限。
4. **刷新业务页面一次**，正常触发请求即可。网站、本页和新接口默认开启，自动发现该页面发起的同源及跨域 API，无需填写 API 前缀、身份方式或逐个开启接口。
5. 点击页面右上角圆按钮查看结果。GET / POST 的完整成功 JSON 响应首次显示 MISS 并写入缓存，之后匹配的请求显示 HIT；可以随时关闭某个接口或设为始终直通。

悬浮圆按钮默认距视口顶部 55px、右侧 35px（使用 right 定位，不设置 left）；已拖动保存的位置继续沿用。

0.7.2 起移除悬浮面板“添加绑定”入口，接口由页面实际请求自动发现。

高级设置保留自定义 API 范围、身份方式、环境、路由和有效期。自动发现不受缓存开关影响；暂停扩展则停止采集。Chrome 授权按主机授予，扩展自身再次精确检查前端网站的协议、主机和端口。自动发现跨域 API 不会给其他前端网站授权。浏览器受限页面不能使用。

## 存储占用与一键清理

打开设置页（点击 Chrome 工具栏的插件图标，或浮窗右上角设置按钮），顶部的“存储与缓存”统一管理本扩展所有网站的数据：

- 响应缓存与预览分别显示份数、正文大小，共享 **100 MiB** 正文预算；过期但未移除的数据也计入实际保留的正文。
- “扩展存储估算”由 Chrome 的 `navigator.storage.estimate()` 提供，包含索引等开销，可能存在延迟或暂不可用；不是整个 Chrome 或业务网站的存储用量。
- 设置页可见时每 5 秒更新，也可点击“刷新统计”。读取失败保留上次结果并提示重试。
- 点击“一键清理缓存”即可清理所有网站的响应缓存、预览及请求记录，保留网站授权、页面与接口规则、开关和已发现的 API 范围，不清理其他网站的 Cookie、localStorage 或 Chrome HTTP 缓存。
- 清理前已发出的请求不会在返回后写回旧缓存。之后新发出的请求按原规则重新录制；没有可清理数据时按钮禁用。
- 清理不会刷新业务页面；页面已显示的数据保持不变。配置与必要索引仍会占用空间，因此浏览器估算不会保证归零。

缓存管理只允许扩展设置页调用，业务页面不能读取全部存储统计或发起全局清理。浮窗继续保留当前页面的“清空本页”操作。

## 强制缓存

可缓存接口的状态右侧按需提供“强制缓存”按钮，折叠状态即可点击。**首次请求（FIRST_REQUEST）和缓存命中（HIT）时隐藏按钮，包括已开启态。** 参数变化、过期、手动重发等其他状态继续显示；开启时按钮文字为“强制缓存中”。隐藏按钮不会关闭已开启的模式，需要关闭时可先点击“重新请求”，待显示手动重发状态后再关闭强制缓存。适用于本地调试中参数持续变化、但希望重复使用同一份响应的接口，例如菜单事件上报。开启后按钮显示“强制缓存中”，忽略全部 Query 与 JSON Body 差异；无需逐个填写要忽略的字段。

切换模式会清除此接口的旧缓存。下一次成功请求录制后，后续不同参数复用同一份响应；命中的请求不发送到后端。再次点击即可恢复普通参数匹配，原先的字段忽略规则保留。“重新请求”仍使用当前页面最近一次真实原始参数访问后端并更新缓存。

强制缓存只改变参数匹配，仍按当前页面、接口方法与地址、身份、凭证模式和匹配请求头隔离，并遵守有效期、网站/本页开关与暂停状态。鉴权、始终直通、未允许缓存的写操作，以及不支持的请求/响应仍遵循原有规则。

## 真实请求原因

真实请求状态旁显示未使用缓存的具体原因。支持首次请求、Query/Body 参数变化、匹配请求头或凭证模式变化、缓存过期、手动清空、规则或强制缓存模式切换、身份/会话变化、手动重发、缓存关闭、请求仍在录制、此前未录制以及容量淘汰等情况。悬停可看说明，展开接口后可查看所选参数组的原因。

原因在实际决定访问后端时记录，保留本次访问后端的诊断依据。0.7.3 起，清空后的响应成功写入缓存时，行内和详情提示会从“缓存已清空”更新为“已重新缓存”，悬停仍解释本次真实请求是由清空触发；请求中、失败或未录制时不会误报成功。MISS 仍表示这次走了真实请求，下一次命中才显示 HIT。其他原因保持原展示；请求失败或响应不支持缓存会另行显示结果。HIT 不显示旧的未命中原因。参数差异按生效的忽略规则和强制缓存模式判断，不展示凭证明文；旧记录缺少诊断信息时显示无可用缓存，不推断成参数变化。0.6.0 不改变缓存匹配键，已有有效缓存继续可用。

## API 范围自动检索

正常操作业务页面即可，**自动发现并直接采用，无需确认**。设置页和浮窗会展示已识别的 API 范围，例如 `http://localhost:8080/api`，并按域名、端口和第一层路径聚合，显示请求方法、接口数量及路径示例。同源代理和跨域 API 均支持。

识别依据是该网站实际请求获得的完整成功 JSON 响应或已有成功缓存命中。静态资源、HTML、失败响应及登录等鉴权接口不计入范围列表。检索只观察页面已有请求，不会主动扫描或额外调用业务接口；列表仅保存地址范围、路径示例与统计，不保存查询参数、请求头或正文。新范围立即参与默认缓存流程，不需要等待列表刷新。

仅需限制范围时再使用高级设置中的自定义模式；该模式继续遵循手填范围，不自动扩大。查看范围列表不会更改缓存规则、清空缓存或覆盖正在编辑的网站设置。

范围列表每站保留最近 50 组、全扩展最多 500 组；每组最多显示 3 个路径示例，超过 200 个不同方法/路径时标为 `200+`。这些是发现列表的存储上限，不限制默认模式中其他接口的缓存资格。

## 更新已有安装

领取新安装包时，**先在 `chrome://extensions` 找到旧的 API Cache Replay，点击“移除”删除旧扩展，再安装新包**。这里的删除指移除 Chrome 中的扩展，不只是删除本地文件夹。

1. 下载最新插件安装 ZIP 并解压到固定位置。
2. 在 Chrome 扩展管理页移除旧的 API Cache Replay，开启“开发者模式”。
3. 点击“加载已解压的扩展程序”（某些 Chrome 界面写作“加载未打包的扩展程序”）。
4. 选择解压后名称形如 `api-cache-replay-0.*.*`、直接包含 `manifest.json` 的文件夹，完成加载；不要选 ZIP 或源码包目录。
5. 重新添加网站、保存并授权，再刷新业务页面。移除旧扩展会清除其本地配置和缓存，新安装需要重新设置与录制。不要同时启用两份 API Cache Replay。

安装后不要删除或移动加载的文件夹。普通使用者无需安装 Node.js；源码开发的构建和重载流程见下一节。

公司内部分享的完整源码包为 `api-cache-replay-source-0.7.5.zip`。解压后进入 `api-cache-replay` 目录；构建、调试及改造入口见 [源码下载与二次开发](docs/SOURCE_DEVELOPMENT.md)。

浏览器测试使用 Playwright 加载实际 `dist` 到临时 Chrome 配置目录，可通过 `CHROME_PATH` 指定 Chrome for Testing 可执行文件。自动测试临时复制扩展，仅向复制品加上本地 fixture 主机权限，以避开自动化中的浏览器授权确认；交付的 manifest 仅有按需主机权限。不会读取或修改日常 Chrome 个人配置。测试完成关闭浏览器并删除临时配置。

## 使用语义

- 页面按精确 History 路径或 Hash 路径隔离，Query 默认不拆页面，可配置用于区分页面的字段。同一接口可绑定多个页面，清空互不影响。请求永远归发起时的页面。
- 接口按方法、API origin 与路径聚合；缓存键包含页面、环境、身份摘要、规则版本、规范化 Query/JSON Body 和选定请求头。重复 Query 值保留顺序，JSON 对象键排序，数组保留顺序。
- 忽略 Query 字段填写字段名；忽略 Body 使用 JSON Pointer，例如 `/pagination/page`。只影响匹配，不修改真实发送的参数。忽略分页会返回同一份已录制数据，不会重新计算分页。
- “重新请求”重发当前标签页最近观察到的原始参数，绕过扩展缓存。关闭缓存时仍可重发允许回放的 GET / POST，但仅更新状态与有界预览。成功缓存时间不会被失败请求或 HIT 修改。
- “重新请求并刷新页面”在缓存开启时等待新缓存保存成功；页面已切换时不会刷新新页面。普通重发只更新扩展数据，不主动更改页面组件状态。
- 原始凭证只留在标签页运行时内存。浏览器或页面重启后，必须由页面再次触发请求才能重新建立手动重发上下文。带一次性 CSRF/签名或敏感 Query/Body 的请求保持直通。
- 默认自动身份：Authorization、token、x-auth-token、api-key 等请求头只以摘要用于分区；没有这些凭证时按浏览器会话与标签页隔离，同一标签页完整刷新和 SPA 导航均可复用对应页面的缓存，无需手填分区。无凭证模式的新标签页、浏览器或扩展重启会建立新分区，后台休眠再唤醒保持分区。对于同源且携带 Cookie 的请求，额外使用可读登录相关 Cookie 的摘要识别变化，忽略分析统计类 Cookie。
- 401/403、网络失败、超时、取消、业务失败不录制。登录/登出和观察到的身份变化使相关旧缓存失效。默认鉴权关键字只匹配最后一个路径段，如 `/api/login`；`/api/login/userInfo` 作为普通查询可缓存。高级设置中以 `/` 开头的自定义规则仍匹配路径前缀。POST 默认允许缓存，具有保存、提交等副作用的 POST 可设为始终直通；PUT/PATCH/DELETE 保持直通，可配置成功后清空本页指定查询缓存。
- 默认 30 分钟 TTL，0 表示手动清空前有效；每份响应最多 1 MiB，缓存与预览总计最多 100 MiB，按最近使用淘汰；调用日志最多 200 条。
- 为本地调试默认允许录制 `Cache-Control: no-store` 响应，可在接口高级规则中关闭。仅录制完整 JSON；排除 204、206、opaque、重定向及流式等响应。

## 结构与取舍

`src/content/main.ts` 在 MAIN world 的 document_start 包装 fetch/XHR，保留原生调用；`src/content/index.ts` 在 ISOLATED world 负责受限消息桥及 Shadow DOM 浮窗；`src/background` 在扩展 Service Worker 中负责权限、规则和扩展来源 IndexedDB。所有代码随扩展打包，不使用远程执行代码、debugger、webRequestBlocking 或代理服务。

TypeScript 严格检查、Vue 3 和固定版本构建依赖让状态与组件边界可验证。缓存判断集中于后台，真实请求始终在原页面发起以保留 Cookie/CORS 语义。Service Worker 从 IndexedDB 恢复状态；保存时核对 generation 和请求序号，阻止清空后回写及旧响应覆盖新响应。桥接失败有界等待并仅回退一次真实请求，保存失败不重复请求。

官方参考：[Chrome 扩展存储与估算](https://developer.chrome.com/docs/extensions/develop/concepts/storage-and-cookies)、[Chrome 内容脚本](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)、[Chrome scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting)、[MessageSender 文档身份](https://developer.chrome.com/docs/extensions/reference/api/runtime/#type-MessageSender)、[storage.session 会话存储](https://developer.chrome.com/docs/extensions/reference/api/storage#property-session)、[Vite Node.js 要求](https://vite.dev/guide/)。本项目最低 Chrome 为 120。

## 已知边界

- 仅顶层页面的普通异步 fetch/XHR JSON。iframe、Worker、自主 Service Worker、WebSocket、SSE、同步 XHR、二进制/文件/流式、上传进度相关请求不覆盖缓存；保留原生请求路线。
- 携带 Body 的 `Request` 对象默认直通，以免读取任意不可重复的请求流；显式通过字符串 `init.body` 提供或替换 JSON 正文时可缓存。
- XHR 为兼容包装，保证常见事件、状态、text/json 与 Axios XHR 适配器流程；不承诺所有反射检查或原生内部特征完全一致。合成 fetch Response 的 url/type/redirected 元数据不完全等同原始响应。
- “真实请求”表示绕过本扩展，浏览器 HTTP 缓存和业务 Service Worker 仍可能参与。计数验收环境不包含这些其他缓存。
- 自动模式不能读取 HttpOnly Cookie 或其他域的 Cookie，也无法保证识别所有自定义登录 Cookie 名称。通过未被观察到的方式切换账号时，应清空该站缓存或关闭后重开标签页；单纯刷新仍会复用同一标签页分区。高级 Cookie 显式分区由用户管理。测试登录过期与权限时需关闭业务缓存；回放不能还原 Set-Cookie 等服务端副作用。
- MAIN 与业务脚本共享执行环境，不能对恶意网站脚本保密；仅对可信开发站点授权。
- 并发首次请求不合并，可能都访问后端。无动态路由模板、云同步、团队协作和商店发布。
